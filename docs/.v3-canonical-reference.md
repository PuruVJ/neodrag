## Shared concepts (referenced by every class)

### `DndNode`
```ts
type DndNode = HTMLElement | SVGElement;
```
The node type a capability can bind. (Sortable is narrower — it binds an `HTMLElement` container only.)

### `Point` / `RectLike` / `Axis`
```ts
type Point = { x: number; y: number };
type RectLike = { left: number; top: number; right: number; bottom: number };
type Axis = 'x' | 'y' | 'both';
```
`Point` exported from `dnd/drag` (constraints). `RectLike` is the DOM-free rect shape used across drag/drop/resize. `Axis` is the drag axis-lock type.

### `EndReason` / `SessionState`
```ts
type EndReason    = 'drop' | 'no-target' | 'cancel';
type SessionState = 'idle' | 'pending' | 'active' | 'completed' | 'cancelled';
```
A normal pointerup ends with `'no-target'`; a capability that commits/cancels from inside passes its own reason. (Sortable treats `reason === 'cancel'` as "don't reorder".)

### `InteractionInput`
The normalized pointer/keyboard/programmatic event every event-data object carries as `input`. Discriminated union on `kind: 'pointer' | 'keyboard' | 'programmatic'`. Common fields: `phase` (`'start'|'move'|'end'`), `clientX`, `clientY`, `target: EventTarget | null`, `modifiers: { shift, ctrl, alt, meta }`, `timestamp`, optional `delta: {x,y}`. Pointer variant adds `native: PointerEvent` + `pointer: { pointerId, pointerType, button, buttons, pressure? }`.

### `data-neodrag-*` marker attributes (full set)

| Constant (export status) | Attribute | Set by | When present |
|---|---|---|---|
| `DRAG_MARKER` (internal) | `data-neodrag-dragging` | `Drag` | on the dragged node while a drag is active |
| `DROP_MARKER` (internal) | `data-neodrag-over` | `Drop` | on a drop zone while a drag is over it |
| `RESIZE_HANDLE_ATTR` (**exported**) | `data-neodrag-resize-handle` | *authored by you* on the handle element; its value is the `ResizeEdge` (e.g. `"se"`). `Resize` reads it to claim the pointerdown. |
| `SORTABLE_KEY_ATTR` (**exported**) | `data-sortable-key` | *authored by you* on each sortable item; value = the item's key. `Sortable` reads it to resolve/measure items. |
| `DRAGGING_MARKER` (internal) | `data-neodrag-sortable-dragging` | `Sortable` | on the dragged item during a sort |
| `SORTABLE_LIFTED_ATTR` (**exported**) | `data-neodrag-sortable-lifted` | `Sortable` lift | on the dragged item while lifted to `position:fixed` |
| `PLACEHOLDER_ATTR` (internal) | `data-neodrag-sortable-placeholder` | `Sortable` lift | on the inserted placeholder reserving the gap |

## 1. `Dnd` — the engine

Semantics-free engine. Owns one document-level sensor delegation, the single active session, and routes pointer input to whichever capability claims a node. Knows nothing about drag/drop/resize.

### Constructor
```ts
new Dnd(options?: CreateDndOptions)
```
```ts
interface CreateDndOptions {
  delegate?: () => HTMLElement;   // element to attach the single document-level listeners. Default: () => document.documentElement
  defaultSensors?: boolean;       // auto-install pointer + keyboard sensors. Default: true
}
```

### Properties
| Member | Type | Notes |
|---|---|---|
| `host` | `SensorHost` | readonly. The sensor wiring object (`getDelegate`, `onInteractionStart/Move/End`, `cancelActive`, …). |
| `session` | `DndSession \| null` | getter. The active interaction (read-only view), or `null`. |

### Methods
| Method | Signature | Behavior |
|---|---|---|
| `use` | `use(...capabilities: Capability[]): this` | Compose capabilities; re-sorts by `priority` desc (default 0), recomputes observers, ensures sensors installed. Chainable. |
| `registerSensor` | `registerSensor(sensor: Sensor): this` | Add a custom sensor (deduped by `sensor.key`); sets it up immediately if sensors already installed. Chainable. |
| `dispose` | `dispose(): void` | Cancels any active session (`'cancel'`), runs all sensor cleanups, marks sensors uninstalled. |

### Routing behavior (observable contract)
- On pointerdown the engine asks each capability (priority order) `resolve(input)`; first non-null `ResolvedTarget` claims the session. Right-click (`button === 2`) is ignored. Only one session at a time.
- The claiming capability's `shouldStart` gates start (default pass); on pass, `start` runs, pointer capture is taken (best-effort), then `move` each move, `end` on pointerup/cancel.
- After the owner's own `start`/`move`/`end`, every *other* capability with an `observe` method is notified (this is how `Drop` watches `Drag`).

### `Capability` interface (what `use()` accepts)
```ts
interface Capability {
  readonly key: symbol;
  readonly name: string;
  readonly priority?: number;                         // higher = resolved first. Default 0
  resolve(input: InteractionInput): ResolvedTarget | null;
  shouldStart?(session: DndSession): boolean;          // threshold gate; default pass
  start(session: DndSession): void;
  move(session: DndSession): void;
  end(session: DndSession, reason: EndReason): void;
  observe?(session: DndSession, phase: 'start'|'move'|'end', reason?: EndReason): void;
}
```

### `ResolvedTarget` / `DndSession`
```ts
interface ResolvedTarget { node: DndNode; data?: unknown; }   // data is capability-private state

interface DndSession {
  state: SessionState;
  readonly capability: Capability;
  readonly target: ResolvedTarget;
  readonly pointerId: number;
  readonly startInput: InteractionInput;   // input at pointerdown
  input: InteractionInput;                 // latest input
  data?: unknown;                          // shared payload (drag sets dragData here; observers read it)
  started: boolean;                        // true once threshold passed + start() ran
  end(reason: EndReason): void;            // commit/cancel from inside a capability
}
```

## 2. `sharedEngine` / `sharedCapability`

Process-wide singletons so every ergonomic class registers into ONE `Dnd` (lets capabilities observe each other — drop watches drag).

```ts
function sharedEngine(): Dnd;                                  // lazily creates one global Dnd
function sharedCapability<T extends Capability>(
  token: unknown, make: () => T
): T;                                                          // memoizes one capability per token, registering it into sharedEngine() on first creation
```
`token` is the capability class itself (e.g. `Drag`), so referencing only `Draggable` references only `Drag` — `Drop`/`Resize`/`Sortable` stay out of the bundle.

## 3. Drag — `Draggable`, `Drag`, `DragHandle`, `DragState`

### `DragOptions`
```ts
interface DragOptions {
  axis?: Axis;                              // 'x' | 'y' | 'both'. Lock to one axis. Default: free (both)
  bounds?: BoundsInput;                     // constrain movement (see below). Default: none
  grid?: readonly [number, number];         // snap [stepX, stepY] px; a 0 step leaves that axis free. Default: none
  handle?: string | HTMLElement;            // only start if pointerdown lands inside this. String → querySelectorAll (trusted/static selector only). Default: whole node
  cancel?: string | HTMLElement;            // never start if pointerdown lands inside this. String → querySelectorAll. Default: none
  disabled?: boolean;                       // when true, resolve() returns null (no drag). Default: false
  threshold?: number;                       // px movement before drag begins (squared-distance gate). Default: 0 (immediate)
  position?: Point;                         // initial / controlled offset. Applied as a translate on bind. Default: {x:0,y:0}
  dragData?: unknown;                       // payload exposed to drop zones (their accepts/onDrop read it via session.data)
  use?: DragPlugin[];                       // tier-2 extension plugins (@neodrag/extend). Static array, no reactivity
  onDragStart?: (e: DragEventData) => void;
  onDrag?:      (e: DragEventData) => void;
  onDragEnd?:   (e: DragEventData) => void;
}
```

### `BoundsInput`
```ts
type BoundsInput = 'parent' | 'viewport' | HTMLElement | RectLike | (() => RectLike);
```
Resolved at drag-start: `'parent'` → `node.parentElement` rect (undefined if no parent); `'viewport'` → `{left:0, top:0, right: innerWidth, bottom: innerHeight}`; function → called for a `RectLike`; `HTMLElement` → its `getBoundingClientRect()`; a `RectLike` → used as-is. Bounds clamp against the element's *untranslated* layout box (so it can't escape across successive drags); if the element is larger than the bounds on an axis it pins to the start edge.

### `DragEventData`
```ts
interface DragEventData {
  offset: Point;            // current applied offset (fresh copy)
  node: DndNode;
  input: InteractionInput;
}
```

### `DragPlugin` (tier-2 seam)
```ts
interface DragPlugin {
  name?: string;
  onStart?(ctx: DragEventData): void;
  onMove?(ctx: DragEventData): Point | void;   // may return an adjusted offset
  onEnd?(ctx: DragEventData): void;
}
```
Constraint pipeline order on each move: **axis → grid → bounds**, then each `use` plugin's `onMove` (a returned `Point` overrides).

### `Draggable` (ergonomic)
```ts

```

|---|---|---|
| `update` | `update(options: Partial<DragOptions>): void` | Fine-grained: only provided keys are written. Updating `position` while not dragging re-applies the translate immediately. |
| `offset` | `get offset(): Point` | Current applied offset. |
| `isDragging` | `get isDragging(): boolean` | True between start and end. |
| `destroy` | `destroy(): void` | Unbinds, clears the translate, removes the `data-neodrag-dragging` marker. |

Sets attribute `data-neodrag-dragging` on the node while dragging.

## 4. Drop — `Droppable`, `Drop`, `DropHandle`, `DropState`

Drop never claims a pointerdown — it **observes** drag sessions and hit-tests registered zones through a pluggable `CollisionIndex`.

### `DropOptions` (per zone)
```ts
interface DropOptions {
  accepts?: (ctx: { dragNode: DndNode; data: unknown }) => boolean;  // filter which drags this zone accepts. data = the drag's dragData. Default: accept all
  collision?: CollisionPolicy;        // tie-break policy. Default: 'pointer'
  priority?: number;                  // higher wins ties first. Default: 0
  hitExpand?: number;                 // grow the hit rect by N px each side. Default: 0
  onEnter?: (e: DropEventData) => void;
  onOver?:  (e: DropEventData) => void;   // fires on the single best zone each move
  onLeave?: (e: DropEventData) => void;
  onDrop?:  (e: DropEventData) => void;   // fires on the single best zone at release
}
```

### `DropEngineOptions` (engine-wide, one per `Drop`, passed to its constructor)
```ts
interface DropEngineOptions {
  dropPointerSamples?: DropSampleMode | DropSampler;  // multi-point hit-testing. Default 'pointer' (cursor only)
  coalesce?: boolean;                                  // collapse N moves/frame into 1 hit-test (rAF). Default false (sync per move)
  index?: () => CollisionIndex<DropState>;             // swap the spatial-index backend. Default LinearCollisionIndex
}
```

### `CollisionPolicy`
```ts
type CollisionPolicy = 'pointer' | 'closestCenter' | 'closestEdge' | 'intersection';
```
Ranking is: highest `priority` wins; ties broken by whichever policy a candidate prefers — `closestCenter` (nearest rect center), `closestEdge` (nearest rect edge, good for list inserts), `intersection` (max overlap area with the dragged element's rect). `'pointer'` does no tie-break.

### `DropSampleMode` / `DropSampler`
```ts
type DropSampleMode = 'pointer' | 'corners' | 'edges' | 'center' | 'all';
type DropSampler = (ctx: { pointer: Point; rect: RectLike | null }) => Point[];
```
- `'pointer'` — just the cursor (cheapest, legacy). `'corners'` — pointer + 4 rect corners. `'edges'` — pointer + corners + 4 edge midpoints. `'center'` — pointer + rect center. `'all'` — all of the above. A function is a custom sampler. The default `'pointer'` mode skips measuring the drag rect entirely.

### `DropEventData`
```ts
interface DropEventData {
  zone: DndNode;
  dragNode: DndNode;
  data: unknown;                 // the drag's dragData (session.data)
  input: InteractionInput;
}
```

### `Droppable` (ergonomic)
```ts
new Droppable(node: DndNode, options?: DropOptions)   // options default {}
```
> Note: `Droppable` uses `sharedCapability(Drop, () => new Drop())`, i.e. the engine-wide `Drop` is created with **default** `DropEngineOptions`. To set `dropPointerSamples`/`coalesce`/`index`, construct a `Drop` yourself and register it via `Dnd.use`.

| Member | Signature | Notes |
|---|---|---|
| `update` | `update(options: Partial<DropOptions>): void` | Merges provided keys into the zone options. |
| `destroy` | `destroy(): void` | Unbinds the zone, removes `data-neodrag-over`. |

Sets attribute `data-neodrag-over` on the zone while a drag is over it.

### `Drop` (capability) — `implements Capability`
`key = Symbol('neodrag.drop')`, `name = 'drop'`. `resolve` always returns `null` (never owns a pointerdown); `start`/`move`/`end` are no-ops; all work happens in `observe`.

```ts
new Drop(options?: DropEngineOptions)   // options default {}
```
| Member | Signature | Notes |
|---|---|---|
| `bind` | `bind(node: DndNode, options?: DropOptions): DropHandle` | Register a zone. |
| `observe` | `observe(session, phase, reason?)` | start → arm rect-invalidation + reset counters; move → hit-test (coalesced or sync); end → commit `onDrop` on the best zone, leave all. |
| `hitCount` | `get hitCount(): number` | @internal — # of hit-tests run (test assertion of coalescing). |
| `pendingFrame` | `get pendingFrame(): boolean` | @internal — true while a coalesced frame is queued. |
| `_unbind` | `_unbind(node): void` | @internal. |

Zone rects are measured once per drag and reused; scroll/resize during the drag invalidates them.

### `DropHandle`
Returned by `Drop.bind`. Members: `update(options: Partial<DropOptions>): void`, `destroy(): void`.

### `DropState`
Per-zone state. `new DropState(node, options)`. Fields: `isOver: boolean`, `rect: RectLike | null` (cached at drag-start), `node` (readonly), `options` (public).

### Collision helpers (also exported from `dnd/drop`)
- `LinearCollisionIndex<T>` / `VirtualCollisionIndex<T>` — both `implements CollisionIndex<T>` (`insert`/`update`/`remove`/`clear`/`query(x,y)`). `VirtualCollisionIndex` takes `{ visible?: () => Iterable<T> }` so `query` scans only on-screen ids (O(visible)).
- `rankDrop(candidates, x, y, ctx?)`, `centerDistanceSq`, `edgeDistanceSq`, `intersectionArea` — pure ranking/geometry functions. Types: `CollisionIndex<T>`, `RankCandidate { rect; priority; policy }`, `RankContext { probeRect? }`.
- `RafBatch<T>` — `new RafBatch(run)`; `schedule(v)`, `flush(v)`, `cancel()`, `get scheduled`.
- `resolveSampler(mode)` → `DropSampler`.

## 5. Resize — `Resizable`, `Resize`, `ResizeHandle`, `ResizeState`

Claims pointerdowns on an element marked `data-neodrag-resize-handle="<edge>"`, at `priority = 100` (above drag, so the handle wins over the body). px-only; unit preservation is an opt-in plugin.

### `ResizeEdge`
```ts
type ResizeEdge = 'n' | 's' | 'e' | 'w' | 'ne' | 'nw' | 'se' | 'sw';   // edges + corners
```
Set as the **value** of `data-neodrag-resize-handle` on each handle element you author (e.g. `data-neodrag-resize-handle="se"`).

### `ResizeSizeBounds` (min/max, mixed into options)
```ts
interface ResizeSizeBounds {
  minWidth?: number; minHeight?: number; maxWidth?: number; maxHeight?: number;   // px clamps. Default: unbounded
}
```

### `ResizeOptions extends ResizeSizeBounds`
```ts
interface ResizeOptions extends ResizeSizeBounds {
  aspectRatio?: number | boolean;   // lock ratio. true = keep initial w/h ratio; number = explicit width/height. Default: off
  bounds?: ResizeBoundsInput;       // container the resize can't spill out of (see below). Default: none
  disabled?: boolean;               // resolve() returns null when true. Default: false
  use?: ResizePlugin[];             // tier-2 plugins (e.g. preserveUnits()). Static array. Default: none
  onResizeStart?: (e: ResizeEventData) => void;
  onResize?:      (e: ResizeEventData) => void;
  onResizeEnd?:   (e: ResizeEventData) => void;
}
```
Size pipeline each move: **pointer-delta size → aspect (if set) → min/max clamp → bounds clamp** (bounds run last but re-apply min after), then `use` plugins' `onMove` (a returned `{width,height}` overrides).

### `ResizeBoundsInput`
```ts
type ResizeBoundsInput = 'parent' | 'viewport' | HTMLElement | RectLike | (() => RectLike);
```
Same vocabulary as drag bounds. The fixed (anchored) edge is pinned; the moving edge can travel only until it reaches the bound. Helpers `resolveResizeBounds` / `clampSizeToBounds` and type `ResizeBoundsContext { readonly startRect: RectLike; readonly inverseScale: number }` are exported.

### `ResizeEventData`
```ts
interface ResizeEventData {
  width: number;          // current px width
  height: number;         // current px height
  edge: ResizeEdge;       // the active handle edge
  node: DndNode;
  input: InteractionInput;
}
```

### `ResizePlugin` / `ResizePluginContext` (tier-2 seam)
```ts
interface ResizePlugin {
  name?: string;
  onStart?(ctx: ResizePluginContext): void;
  onMove?(ctx: ResizePluginContext): { width: number; height: number } | void;
  onEnd?(ctx: ResizePluginContext): void;
}
interface ResizePluginContext {
  size:    { width: number; height: number };   // current frame px size
  initial: { width: number; height: number };   // px size at resize-start
  anchor:  ResizeEdge;
  node: DndNode;
  input: InteractionInput;
}
```
`preserveUnits(): ResizePlugin` — exported plugin that reads the authored unit (`%`, `rem`, …) on start, resizes in px, and commits the final size back in the original unit on end.

### SVG handling
HTML elements get CSS `width`/`height`. SVG *geometry* elements (`rect`, `image`, `foreignObject`, `svg`, `use`) get the `width`/`height` **attributes**; other SVG elements (`g`, `path`) fall back to CSS. Inverse-scale compensation is applied to the pointer delta.

## 6. Sortable — `SortableList`, `Sortable`, `SortableHandle`, `SortableContext`

Per-container reordering. Pipeline: measure (variable sizes) → resolve insert (anchor, with hysteresis) → project displacement (1D list shift or 2D grid shift) → commit (FLIP). Optionally lifts the dragged node to `position:fixed`. Grouped containers exchange items via a cross-container transfer registry.

Each sortable item must carry `data-sortable-key="<key>"` (`SORTABLE_KEY_ATTR`). The capability binds an **`HTMLElement` container**, not individual items.

### `SortableOptions<T = unknown>`
```ts
interface SortableOptions<T = unknown> {
  items: T[];                                  // current ordered items (framework re-pushes a snapshot on change). Required
  keyOf: (item: T) => string;                  // stable key per item. Required
  onReorder: (next: T[], op: MoveOp) => void;  // reordered array + anchor move op. Required
  onCommit?: (op: MoveOp) => void;             // pure op stream (what @neodrag/collab subscribes to); fires on every commit
  onTransfer?: (op: TransferOp<T>) => void;    // cross-container move — fires on the TARGET container when an item transfers in
  axis?: SortAxis;                             // 'x' | 'y'. Default 'y'
  strategy?: SortStrategy;                      // 'list' (1D midpoint crossing) | 'grid' (2D closest-center). Default 'list'
  group?: string;                              // cross-container transfer group; containers sharing it can exchange items. Default: none
  animation?: boolean | number;                // FLIP on reorder. true→200ms, number→ms, false→off. Default true
  lift?: boolean;                              // lift dragged node onto position:fixed above siblings. Default false
  foreignProximity?: number;                   // px band a foreign column must be within to be eligible. Default: auto (max(24, min(w,h)*0.35))
  hysteresis?: number;                         // px the pointer must cross past a slot boundary before the gap flips. Default 3
}
```
```ts
type SortAxis     = 'x' | 'y';
type SortStrategy = 'list' | 'grid';
```

### `MoveOp` (anchor-based, CRDT-ready)
```ts
interface MoveOp {
```

```ts
interface TransferOp<T = unknown> {

}
```

## 1. Tier-2 Extensions — the `use: []` seam (`src/dnd/extend/`)

### 1.1 Authoring contract: `DragPlugin`

Defined in `src/dnd/drag/drag.ts`. A **plain object** — no reactive slots, no reconcile machinery, no symbol key (that's the tier-1 capability-plugin world). Passed to the drag capability via `DragOptions.use: DragPlugin[]` (a *static* array, no reactivity).

```ts
export interface DragEventData {
  offset: Point;            // current committed offset {x,y}
  node: DndNode;            // the dragged element (HTMLElement | SVGElement)
  input: InteractionInput;  // normalized input that drove this tick
}

export interface DragPlugin {
  name?: string;
  onStart?(ctx: DragEventData): void;
  onMove?(ctx: DragEventData): Point | void;   // return an adjusted offset to override
  onEnd?(ctx: DragEventData): void;
}
```

Lifecycle (from `drag.ts`): on start, every `use[]` plugin's `onStart` fires; on each move, `onMove` runs and **may return a `Point` to replace the proposed offset** (plugins run in array order, each sees the previous one's adjusted `offset`); on end, `onEnd` fires. Note: `use:[]` runs **only after a drag has begun** — there is no start-veto here (use the core `handle`/`cancel`/`disabled` options for hard start gating).

Minimal custom extension:

```ts
import type { DragPlugin } from '@neodrag/core/dnd'; // DragPlugin is part of the drag surface
const clampX: DragPlugin = {
  name: 'clamp-x',
  onMove: ({ offset }) => ({ x: Math.max(0, offset.x), y: offset.y }),
};
// usage: draggable(node, { use: [clampX] })
```

### 1.2 Built-in extension factories (`src/dnd/extend/index.ts`)

| Factory | Signature | Behavior |
|---|---|---|

### 1.3 `controls` zone API (`src/dnd/extend/controls.ts`)

Pure, exported for testing. `ControlFrom` builds zones; `resolveControl` is the allow/block tie-break ladder ported faithfully from the legacy plugin.

```ts
export type ZonesFrom = (root: Element) => ControlZone[];
export const ControlFrom: {
  selector(selector: string): ZonesFrom;          // querySelectorAll — trusted/static selectors only
  elements(els: ArrayLike<Element|null|undefined>): ZonesFrom;
};
export function resolveControl(
  allow: ControlZone[], block: ControlZone[], allowDefined: boolean,

export interface ControlsOptions {
```

### 2.2 Registration on the engine (`src/dnd/engine.ts`)

The engine (`Dnd`) owns one document-level delegate and routes input to whichever capability claims a node. Sensors are registered two ways:


```ts
import { Dnd } from '@neodrag/core/dnd';
import { PointerSensor, KeyboardSensor } from '@neodrag/core/sensors';
const engine = new Dnd({ defaultSensors: false })
  .use(/* capabilities */);
```

## 4. Collab — the CRDT-ready layer (`src/dnd/collab/`)

The headline of the "multi-framework, CRDT-ready" rebrand. The core stays **CRDT-agnostic**; collab binds a `SortableHandle`'s CRDT-ready seams to any backend. Home: `@neodrag/core/dnd/collab/index`.

### 4.1 The sortable seams it binds to (`src/dnd/sortable/sortable.ts`)

Reorders are expressed as **anchor-based move ops** (`MoveOp { itemId; afterId: string|null }` — `null` = front), not index splices, so they survive concurrent inserts/deletes (`src/dnd/sortable/reorder.ts`: `applyMove`, `moveOpFromIndices`, `reorderKeys`).

```ts
class SortableHandle<T> {
  update(opts: Partial<SortableOptions<T>>): void;   // collab sets/clears onCommit here
  applyExternal(op: MoveOp): void;                   // replay a remote op through the SAME reorder path
  presence(): SortablePresence | null;               // current in-flight reorder {dragKey, fromIndex, toIndex}
  destroy(): void;
}
// SortableOptions.onCommit?: (op: MoveOp) => void   — the pure durable op stream collab subscribes to
```

### 4.2 The thin binding: `CollabProvider` + `bindCollab` + `MemoryCollab` (`src/dnd/collab/index.ts`)

```ts
export interface CollabProvider {
  sendOp(op: MoveOp): void;                              // publish durable anchor move op
  onRemoteOp(handler: (op: MoveOp) => void): () => void; // subscribe to remote ops
  sendPresence?(presence: SortablePresence | null): void;// optional ephemeral presence
}

export function bindCollab(handle: SortableHandle, provider: CollabProvider): () => void;
// wires handle.update({onCommit: op => provider.sendOp(op)}) outbound,
// and provider.onRemoteOp(op => handle.applyExternal(op)) inbound. Returns teardown.

export class MemoryCollab implements CollabProvider {  // single-process, no network — tests/demos
  connect(other: MemoryCollab): void;
}
```

Headline shallow usage:

```ts
import { bindCollab, MemoryCollab } from '@neodrag/core/dnd/collab/index';
const a = new MemoryCollab(), b = new MemoryCollab();
a.connect(b);
const offA = bindCollab(handleA, a);   // local commits → ops → peer applyExternal
const offB = bindCollab(handleB, b);
```

### 4.3 Deep collab: `CollabSession` (the real engine) (`src/dnd/collab/session.ts`)

The headline. Binds **one `SortableHandle`** to a **`CollabBackend`** (durable op channel + ephemeral presence channel) and runs the full loop: outbound durable ops on commit; inbound ops reconciled through `applyExternal` **and** folded into a `ReconcileEngine` for **mid-drag rebase**; throttled presence broadcast while dragging.

```ts
export interface CollabBackend {
  peerId: string;
  sendOp(op: MoveOp): void;
  onRemoteOp(handler: (op: MoveOp) => void): () => void;
  presence: PresenceTransport;
}
export interface CollabSessionOptions {
  order: string[];                     // canonical key order, kept in lock-step
  presenceThrottleMs?: number;         // default 40
  onRemotePresence?: (peerId, presence: CollabPresence | null) => void; // render peer ghosts
  onRebase?: (insertIndex: number) => void;  // remote op shifted our in-flight insert
}
class CollabSession {
  constructor(handle: SortableHandle, backend: CollabBackend, options: CollabSessionOptions);
  get reconcile(): ReconcileEngine;
  remotePresences(): ReadonlyMap<string, CollabPresence>;
  syncOrder(order: string[]): void;    // re-push when the framework's item array changes
  pump(pointer?: PresencePoint): void; // tick local presence (call from move observer or rAF) — deterministic
  dispose(): void;
}
```

```ts
import { CollabSession, MemoryBackend } from '@neodrag/core/dnd/collab/index';
const [backA, backB] = MemoryBackend.pair('alice', 'bob');  // connected op + presence channels
const session = new CollabSession(handleA, backA, {
  order: items.map(keyOf),
  onRemotePresence: (peer, p) => renderGhost(peer, p),
  onRebase: (i) => console.log('in-flight insert shifted to', i),
});
// in the sortable move observer: session.pump({ x: e.clientX, y: e.clientY });
```

`MemoryBackend` (in `index.ts`) is a complete in-process `CollabBackend` (`MemoryCollab` + `MemoryPresence`); `MemoryBackend.pair(idA, idB)` builds two connected peers for two-peer tests.

### 4.4 `ReconcileEngine` — the order algebra (`src/dnd/collab/reconcile.ts`)

Pure/DOM-free. Owns the optimistic-local order and performs **mid-drag rebase**: when a remote op lands during a local drag, it applies the op to the canonical order then **re-resolves the same stable anchor** — so the drag continues and the ghost stays after the same neighbour even as absolute indices shift.

```ts
export interface InsertAnchor { itemId: string; afterId: string | null; }       // null = front
export interface RebaseResult { order: string[]; inflight: InsertAnchor|null; insertIndex: number; rebased: boolean; }
export function anchorFor(order, itemId, toIndex): InsertAnchor;
export function resolveInsertIndex(order, anchor): number;
class ReconcileEngine {
  constructor(initial: readonly string[]);
  get order; get inflight; get isDragging; get insertIndex;
  syncOrder(order); beginLocal(presence); updateLocal(presence); endLocal(committedOp?);
  applyRemote(op: MoveOp): RebaseResult;   // the rebase
  snapshot(): ReconcileState;
}
```

# Neodrag v3 — Per-Framework Usage Reference

All v3 wrappers are thin adapters over the class-based core in `@neodrag/core/dnd`
(`Draggable`, `Droppable`, `Resizable`, `SortableList`, plus extension plugins via `use: []`).
Each framework package exposes a framework-idiomatic factory per capability and re-exports the
core classes/types. Verified against the actual wrapper source.

## Core option shapes (shared by all frameworks)

```ts
interface DragOptions {
  axis?; bounds?; grid?; handle?; cancel?; disabled?;
  threshold?; position?; dragData?;
  use?: DragPlugin[];                 // tier-2 extensions (from @neodrag/extend) — static, non-reactive
  onDragStart?(e); onDrag?(e); onDragEnd?(e);
}
interface DropOptions {
  accepts?(ctx: { dragNode; data }): boolean;
  collision?; priority?; hitExpand?;
  onEnter?(e); onOver?(e); onLeave?(e); onDrop?(e);
}
interface ResizeOptions {  // extends { minWidth?, minHeight?, maxWidth?, maxHeight? }
  aspectRatio?: number | boolean; bounds?; disabled?;
  use?: ResizePlugin[];              // e.g. preserveUnits() — static, non-reactive
  onResizeStart?(e); onResize?(e); onResizeEnd?(e);
}
interface SortableOptions<T> {
  items: T[]; keyOf(item): string;
  onReorder(next: T[], op: MoveOp): void;
  onCommit?(op); onTransfer?(op);
  axis?; strategy?: 'list' | 'grid'; group?; animation?: boolean | number;
  lift?; foreignProximity?; hysteresis?;
}
```

**Resize handles** are child elements carrying `data-neodrag-resize-handle="<edge>"` where edge is
one of `n e s w ne nw se sw` (default if a handle omits a value: `se`). They are NOT configured via
an option — you place handle elements inside the resizable node.

**`use: [...]` extensions** are imported from `@neodrag/core/dnd` (re-exported by every wrapper),
e.g. `bounds` is an option, but plugins like `ghost`, `autoScroll`, `scrollLock`, `touchAction`,
`controls`, `haptics`, `snapToGrid`, `magnetic`, `onMove`, and (resize) `preserveUnits` go in `use`.

## Svelte — `@neodrag/svelte`

### Public API
```ts
function draggable(options?: DragOptions): { readonly attach; readonly isDragging: boolean };
function droppable(options?: DropOptions): { readonly attach; readonly isOver: boolean };
function resizable(options?: ResizeOptions): {
  readonly attach; readonly isResizing: boolean;
  readonly size: { width; height } | undefined;
};
// re-exported core classes:
export { Draggable, Droppable, Resizable };
// types: DragOptions, DropOptions, ResizeOptions, DragEventData, DropEventData, ResizeEventData, DndNode
```

`attach` is an object keyed by a `createAttachmentKey()` symbol — spread it onto the element so
Svelte 5 runs the attachment. There is **no `ref`**; you spread `{...attach}` (or, equivalently for
a single attachment, use `{@attach ...}`). The factory wraps the lifecycle callbacks once and reads
the latest user handlers through the `options` closure, so it never recreates the core instance.

**Reactivity:** options are closed over once; mutate fields on the same `options` object (or have the
callbacks read reactive `$state`) — the wrapper does not re-instantiate on change.

```svelte
<script>
  import { draggable } from '@neodrag/svelte';
  const drag = draggable({ axis: 'x', bounds: 'parent' });
</script>

<div {...drag.attach} class:dragging={drag.isDragging}>drag me</div>
```

CANONICAL v3 SNIPPET SHAPES (use these everywhere):
- Svelte: `const drag = draggable({ axis: 'x', bounds: 'parent' }); <div {...drag.attach}>` (lowercase `draggable(options)` returning `{ attach, isDragging }`; spread `{...drag.attach}`). NOT `new Draggable({plugins})`, NOT `{@attach drag.attachment}`.
- React: `const { ref, isDragging } = useDraggable({ axis: 'x' }); <div ref={ref}>` (options object, NO ref argument, NO plugin array).
- Vue: `const { ref, isDragging } = useDraggable({ axis: 'x' }); <div :ref="ref">` (composable, NOT a `vDraggable`/`v-draggable` directive).
- Solid: `const { ref, isDragging } = createDraggable({ axis: 'x' }); <div ref={ref}>`.
- Vanilla: `const drag = new Draggable(node, { axis: 'x' }); drag.destroy();` (constructor is `(node, options)`, NOT `new Draggable({plugins}).attach(node)`; `Draggable` comes from `@neodrag/vanilla` === `@neodrag/core/dnd`).
- Capabilities mirror this: `droppable/useDroppable/createDroppable` + core `Droppable`, `resizable/useResizable/createResizable` + core `Resizable`, and `SortableList` (core class `new SortableList(container, { items, keyBy, onReorder })`) — no framework-specific sortable wrapper exists yet.
