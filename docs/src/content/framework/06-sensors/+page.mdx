Sensors listen on the engine **delegate** (usually `document.documentElement`) and call into the session machine. They are **not** per-draggable plugins.

## Registration API

Sensors are **classes** registered on `Neodrag`. There is no `sensors: []` constructor option.

```typescript
import {
  Neodrag,
  PointerSensor,
  KeyboardSensor,
  KeyboardMoveSensor,
  KEYBOARD_MOVE_SENSOR_KEY,
} from '@neodrag/core';

// Default: pointer + Escape cancel + keyboard move (Space / arrows)
const engine = new Neodrag();

// Pointer only
const pointerOnly = new Neodrag({ defaultSensors: false });
pointerOnly.registerSensor(new PointerSensor({ buttons: [0] }));

// Trim a default
const trimmed = new Neodrag();
trimmed.unregisterSensor(KEYBOARD_MOVE_SENSOR_KEY);
```

### `registerSensor(sensor)`

- Adds a sensor instance (must extend `SensorBase` / implement `Sensor`).
- Throws if another sensor with the same `key` is already registered.
- If the engine has already attached sensors (first `draggable` / `droppable`), listeners are wired immediately.

### `unregisterSensor(key)`

- Runs that sensor’s cleanup and removes it from the engine.

### `getSensors()`

- Read-only list of registered sensors (in registration order).

### `defaultSensors` option

| Value | Behavior |
|-------|----------|
| omitted or `true` | Registers `PointerSensor`, `KeyboardSensor`, `KeyboardMoveSensor` |
| `false` | No sensors until you `registerSensor` |

For manual bootstrap after `defaultSensors: false`:

```typescript
import { installDefaultSensors } from '@neodrag/core/sensors';

const engine = new Neodrag({ defaultSensors: false });
installDefaultSensors((sensor) => engine.registerSensor(sensor));
```

## Built-in sensors

| Class | `key` | Role |
|-------|-------|------|
| `PointerSensor` | `POINTER_SENSOR_KEY` | `pointerdown` / move / up → `InteractionInput` (`kind: 'pointer'`) |
| `KeyboardSensor` | `KEYBOARD_SENSOR_KEY` | `Escape` → `cancelActive('cancel')` |
| `KeyboardMoveSensor` | `KEYBOARD_MOVE_SENSOR_KEY` | Space grab + arrows when `keyboardDrag` plugin is on the node |

Resize handle hit-testing still uses the **pointer** path today. Keyboard resize is not a separate sensor yet.

## Custom sensor

Subclass `SensorBase` and implement `attach(host)`:

```typescript
import { SensorBase, type SensorHost, keyboardToInput } from '@neodrag/core';

class MySensor extends SensorBase {
  readonly key = Symbol('my.sensor');

  protected attach(host: SensorHost) {
    const onMove = () => {
      host.onInteractionMove(
        keyboardToInput({
          phase: 'move',
          clientX: 0,
          clientY: 0,
          key: 'ArrowRight',
          delta: { x: 1, y: 0 },
        }),
      );
    };
    // listen(...)
    return () => { /* remove listeners */ };
  }
}

engine.registerSensor(new MySensor());
```

Use `SensorHost.onInteractionStart` / `Move` / `End` — not `PointerEvent` directly. See [keyboard-drag](/plugin/14-keyboard-drag) and `InteractionInput` on the core page.

## Plugins vs sensors

| | Sensors | Plugins (`Draggable` `plugins`) |
|---|---------|----------------------------------|
| Scope | One engine | Per element |
| Job | Raw input → `InteractionInput` | Bounds, grid, events, `keyboardDrag` config, etc. |

`keyboardDrag` is a **plugin** (per-node options). `KeyboardMoveSensor` is the **sensor** that reads that config and drives the engine.
