import FrameworkSwitch from '$components/FrameworkSwitch.astro';

If you used Neodrag v2, the good news is the part you knew best didn't change. v3 **keeps the options-object ergonomics**: `axis`, `bounds`, `grid`, `handle`, `cancel`, `disabled`, `threshold` and `position` are still plain keys on a single options object — no imports, no helper factories, no wrappers around values. You pass the same shapes you always did.

What changed is everything _around_ that object. v3 is a rewrite on a shared, framework-agnostic engine, so it adds capabilities v2 never had (drop zones, resize, sortable lists), a single `use: []` seam for extensions, one normalized input model across pointer/keyboard/programmatic, and an opt-in collab layer for real-time sortable. Two of v2's flags — text-selection suppression and `touch-action` handling — are now **built in and on by default**. And the way you _attach_ a draggable to an element is now consistent across frameworks.

> If you read about a "plugin array" API in an early v3 preview — that design was dropped. There is no `plugins: [...]`, no `@neodrag/*/plugins` subpath, and no `axis()` / `bounds(BoundsFrom…)` factories. Options are plain object keys, exactly like v2.

## What actually changed

| Aspect | v2 | v3 |
| --- | --- | --- |
| Options (`axis`, `bounds`, `grid`, …) | Plain object keys | **Same** — plain object keys |
| Attaching to an element | Action / directive / hook with options | A class instance or hook you spread or assign (see below) |
| Events | `onDrag` etc. with `offsetX`/`offsetY` | Same callback names; data is now `{ offset, node, input }` |
| Bounds string (`'parent'`) | Supported | **Still supported**, plus `'viewport'`, element, rect, function |
| Text selection during drag | `applyUserSelectHack` flag | **Built in** as `userSelect` (on by default) |
| Touch scroll stealing the drag | manual | **Built in** as `touchAction` (axis-aware default) |
| New capabilities | — | `Droppable`, `Resizable`, `SortableList` from the same package |
| Extensions | Built-in only | `use: []` seam (`scrollLock`, `magnetic`, `snapToGrid`, `ghost`, …) |
| Collab / real-time | — | Opt-in `bindCollab` for sortable |
| Imports | Varied per framework | **Everything** from the one framework package |

Everything — wrappers, the `Draggable` / `Droppable` / `Resizable` / `SortableList` classes, extensions, collab — imports from the single framework package: `@neodrag/svelte`, `@neodrag/react`, `@neodrag/vue`, `@neodrag/solid`, `@neodrag/vanilla`. There are no subpaths to remember.

## The one API change you have to make

The options are the same — but how you bind a draggable to an element changed. Here is the same draggable in v2 and v3, side by side.

<FrameworkSwitch>
<div slot="svelte">

**v2 — the `use:draggable` action:**

```svelte
<script>
  import { draggable } from '@neodrag/svelte';
</script>

<div use:draggable={{ axis: 'x', bounds: 'parent', grid: [10, 10] }}>
  Drag me
</div>
```

**v3 — `new Draggable(options)`, spread `{...drag.attach}`:**

```svelte
<script>
  import { Draggable } from '@neodrag/svelte';

  const drag = new Draggable({ axis: 'x', bounds: 'parent', grid: [10, 10] });
</script>

<div {...drag.attach}>Drag me</div>

{#if drag.isDragging}
  <p>Dragging…</p>
{/if}
```

The action is gone. `Draggable` is now a **class** you instantiate in `<script>`; spread its `attach` onto the element. State like `isDragging` is a reactive getter you can read straight in markup.

</div>
<div slot="react">

**v2 — `useDraggable(ref, options)`:**

```tsx
import { useRef } from 'react';
import { useDraggable } from '@neodrag/react';

function Box() {
  const ref = useRef(null);
  useDraggable(ref, { axis: 'x', bounds: 'parent', grid: [10, 10] });
  return <div ref={ref}>Drag me</div>;
}
```

**v3 — the hook owns the ref and returns it:**

```tsx
import { useDraggable } from '@neodrag/react';

function Box() {
  const { ref, isDragging } = useDraggable({
    axis: 'x',
    bounds: 'parent',
    grid: [10, 10],
  });
  return <div ref={ref}>{isDragging ? 'Dragging…' : 'Drag me'}</div>;
}
```

You no longer create the ref yourself or pass it in — `useDraggable(options)` returns `{ ref, isDragging }`. Attach `ref` to the element.

</div>
<div slot="vue">

**v2 — the `v-draggable` directive:**

```vue
<script setup>
import { vDraggable } from '@neodrag/vue';

const options = { axis: 'x', bounds: 'parent', grid: [10, 10] };
</script>

<template>
  <div v-draggable="options">Drag me</div>
</template>
```

**v3 — the `useDraggable` composable + `:ref`:**

```vue
<script setup>
import { useDraggable } from '@neodrag/vue';

const { ref, isDragging } = useDraggable({
  axis: 'x',
  bounds: 'parent',
  grid: [10, 10],
});
</script>

<template>
  <div :ref="ref">{{ isDragging ? 'Dragging…' : 'Drag me' }}</div>
</template>
```

The directive is replaced by a composable. `useDraggable(options)` returns `{ ref, isDragging }` (Vue refs — read `isDragging.value` in script). Bind `ref` with `:ref`.

</div>
<div slot="solid">

**v2 — the `use:draggable` directive:**

```tsx
import { createDraggable } from '@neodrag/solid';

function Box() {
  const { draggable } = createDraggable();
  return (
    <div use:draggable={{ axis: 'x', bounds: 'parent', grid: [10, 10] }}>
      Drag me
    </div>
  );
}
```

**v3 — `createDraggable(options)` returns a ref setter:**

```tsx
import { createDraggable } from '@neodrag/solid';

function Box() {
  const { ref, isDragging } = createDraggable({
    axis: 'x',
    bounds: 'parent',
    grid: [10, 10],
  });
  return <div ref={ref}>{isDragging() ? 'Dragging…' : 'Drag me'}</div>;
}
```

`createDraggable(options)` returns `{ ref, isDragging }`. `ref` is a setter callback you pass to `ref={ref}`; `isDragging` is an accessor — call `isDragging()`.

</div>
<div slot="vanilla">

**v2 — the `draggable(node, options)` function:**

```js
import { draggable } from '@neodrag/vanilla';

const node = document.querySelector('#drag-me');
const { destroy } = draggable(node, {
  axis: 'x',
  bounds: 'parent',
  grid: [10, 10],
});
```

**v3 — `new Draggable(node, options)`:**

```js
import { Draggable } from '@neodrag/vanilla';

const node = document.querySelector('#drag-me');
const drag = new Draggable(node, {
  axis: 'x',
  bounds: 'parent',
  grid: [10, 10],
});

// later
drag.update({ axis: 'y' });
drag.destroy();
```

The function becomes a class. `new Draggable(node, options)` gives you `.update(partial)`, `.offset`, `.isDragging` and `.destroy()`. Note the node comes **first** here — only the Svelte class is options-only.

</div>
</FrameworkSwitch>

That's the entire breaking surface for a basic draggable. Same options, new attach idiom.

## Options mapping: v2 → v3

Almost all v2 options carry over **unchanged** as plain object keys. A few got more capable, two became always-on built-ins, and a couple moved out to the extensions seam.

| v2 option | v3 | Notes |
| --- | --- | --- |
| `axis: 'x' \| 'y' \| 'both'` | `axis` (same) | Still a plain string. |
| `bounds: 'parent'` | `bounds: 'parent'` | **Legacy string still works**, and now also `'viewport'`, an `HTMLElement`, a `{ left, top, right, bottom }` rect, or `() => rect`. |
| `grid: [number, number]` | `grid` (same) | Snap offset to `[stepX, stepY]` px. |
| `handle: string \| HTMLElement` | `handle` (same) | Only start a drag from inside this. |
| `cancel: string \| HTMLElement` | `cancel` (same) | Never start a drag from inside this. |
| `disabled: boolean` | `disabled` (same) | When `true`, dragging never starts. |
| `threshold: { distance, delay }` | `threshold: number` | Now a single number — px of movement before a drag begins (default `0`). |
| `position: { x, y }` | `position` (same) | Controlled / initial offset — bind reactive state to drive it (now two-way). |
| `defaultPosition: { x, y }` | `position: { x, y }` | One option now; pass it once for the initial offset. |
| `applyUserSelectHack: boolean` | `userSelect: boolean` _(built in, on by default)_ | Text selection is suppressed during a drag automatically; pass `userSelect: false` to allow it. **Delete the v2 flag** — `true` is the default. |
| `onDragStart` / `onDrag` / `onDragEnd` | same names | Callback **data shape changed** — see below. |
| `ignoreMultitouch` | _built in_ | Handled by the engine; no option needed. |
| `transform` | _removed_ | Use a `use: []` extension returning an offset from `onMove`. |

The `dragData` option is new in v3 — it's the payload your drop zones read. `touchAction` is also new and built-in: a CSS `touch-action` (axis-aware default — `pan-y` for `axis: 'x'`, `pan-x` for `axis: 'y'`, `none` for free drag) is applied at bind so a touch drag isn't stolen by native scroll. You rarely need to touch it; pass a custom string or `touchAction: false` to opt out. And `use: []` is the new home for behavior that used to be a flag.

> v2's `applyUserSelectHack` did **not** become `scrollLock()`. `userSelect` (text selection) and `scrollLock` (preventing page scroll while dragging) are different concerns — `scrollLock` is an opt-in extension covered in [Extras](/docs/extras), and you only reach for it when you want to freeze the page, not to stop text highlighting.

### Event data changed shape

Events keep their names (`onDragStart`, `onDrag`, `onDragEnd`) but the object you receive is different. v2 gave you flat `offsetX` / `offsetY` plus `rootNode` and the raw event. v3 gives you a structured `DragEventData`:

```ts
{ offset: { x, y }, node, input }
```

`offset` replaces `offsetX`/`offsetY`, `node` is the dragged element, and `input` is the normalized `InteractionInput` — a discriminated union over pointer / keyboard / programmatic. When `input.kind === 'pointer'`, the raw `PointerEvent` is at `input.native`. The input model is covered in [Sensors](/docs/sensors).

## Reactivity got simpler, not harder

In v2 you handed the wrapper a fresh options object and it reconciled. v3 works the same way — there are **no compartments, no thunks**. Keep your reactive state in the options object; the wrapper reads the latest values and pushes a fine-grained update without recreating the draggable.

<FrameworkSwitch>
<div slot="svelte">

```svelte
<script>
  import { Draggable } from '@neodrag/svelte';

  let axis = $state('x');
  const drag = new Draggable({
    get axis() {
      return axis;
    },
    bounds: 'parent',
  });
</script>

<div {...drag.attach}>Drag me</div>
<button onclick={() => (axis = axis === 'x' ? 'y' : 'x')}>Toggle axis</button>
```

Wrap reactive values in a **getter** so the wrapper always reads the current `axis` and pushes `update()`.

</div>
<div slot="react">

```tsx
import { useState } from 'react';
import { useDraggable } from '@neodrag/react';

function Box() {
  const [axis, setAxis] = useState<'x' | 'y'>('x');
  const { ref } = useDraggable({ axis, bounds: 'parent' });

  return (
    <>
      <div ref={ref}>Drag me</div>
      <button onClick={() => setAxis((a) => (a === 'x' ? 'y' : 'x'))}>
        Toggle axis
      </button>
    </>
  );
}
```

Just put state in the options each render — the hook reconciles.

</div>
<div slot="vue">

```vue
<script setup>
import { ref as vueRef } from 'vue';
import { useDraggable } from '@neodrag/vue';

const axis = vueRef<'x' | 'y'>('x');
const { ref } = useDraggable({
  get axis() {
    return axis.value;
  },
  bounds: 'parent',
});
</script>

<template>
  <div :ref="ref">Drag me</div>
  <button @click="axis = axis === 'x' ? 'y' : 'x'">Toggle axis</button>
</template>
```

Reactive option values go through **getters** that read `.value`.

</div>
<div slot="solid">

```tsx
import { createSignal } from 'solid-js';

      return axis();

  return (
    <>

      <button onClick={() => setAxis((a) => (a === 'x' ? 'y' : 'x'))}>

      </button>

```

Reactive option values go through **getters** that call the signal.

</div>
<div slot="vanilla">

```js
import { Draggable } from '@neodrag/vanilla';

const node = document.querySelector('#drag-me');
const drag = new Draggable(node, { axis: 'x', bounds: 'parent' });

// reactivity is explicit and fine-grained — only changed keys are written

  drag.update({ axis: drag.offset.x ? 'y' : 'x' });
});
```

`update()` merges only the keys you pass — no destroy/recreate.

## What's new (and worth migrating toward)

These had no v2 equivalent. All import from the same package and tree-shake — importing only the draggable won't pull any of them in.

- **Extensions via `use: []`** — opt-in behaviors like `scrollLock()`, `snapToGrid()`, `magnetic()`, `ghost()`, `haptics()`, `autoScroll()`. This is also the seam for your own custom logic: a plain object whose `onMove` may return a `{ x, y }` to override the offset. See [Extras](/docs/extras).
- **Drop zones** — `Droppable` / `useDroppable`. Drop observes drag automatically on the shared engine; pair it with `dragData` and `accepts`. See [Droppable](/docs/droppable).
- **Resize** — `Resizable` / `useResizable`, with `data-neodrag-resize-handle="se"` handles you author. See [Resizable](/docs/resizable).
- **Sortable lists** — `SortableList`, with FLIP animation, grid strategy and cross-container groups. Each row gets `{...list.row(item.id)}` instead of a hand-written attribute. See [Sortable](/docs/sortable).
- **Real-time collab** — `bindCollab` wires a sortable's anchor-based move ops to any backend (Yjs, Liveblocks, your transport). The ops are designed to survive concurrent edits. See [Collaboration](/docs/collaboration).

## Migration checklist

1. **Update the package** to `@neodrag/<framework>@next`. Everything still comes from that one import — delete any `/plugins` or other subpath imports.
2. **Keep your options object.** `axis`, `bounds`, `grid`, `handle`, `cancel`, `disabled`, `position` are unchanged.
3. **Collapse `threshold`** from `{ distance, delay }` to a single number.
4. **Merge `defaultPosition` into `position`** (one option now).
5. **Delete `applyUserSelectHack`** — text-selection suppression is built in (`userSelect`, on by default). Only pass `userSelect: false` if you _want_ selection during a drag.
6. **Swap the attach idiom** — action → `new Draggable(options)` + `{...drag.attach}` (Svelte), `useDraggable(ref, opts)` → `const { ref } = useDraggable(opts)` (React), directive → `useDraggable` composable (Vue), directive → `createDraggable(opts).ref` (Solid), `draggable(node, opts)` → `new Draggable(node, opts)` (vanilla).
7. **Update event handlers** to read `offset.x` / `offset.y` (and `input` for the raw event) instead of `offsetX` / `offsetY`.
8. **Drop `ignoreMultitouch` and `transform`** — the first is built in; the second becomes a `use: []` extension returning an offset from `onMove`.

That's it. The mental model you built with v2 — "configure a draggable with an options object" — is exactly the v3 model. v3 just gives that object a bigger, more consistent world to live in.
