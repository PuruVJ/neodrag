A **droppable** turns any element into a drop zone. Drop zones auto-observe every drag on the page — there is no registration, no shared context, no wiring between a draggable and a zone. Make a node draggable, make another node droppable, and the engine hit-tests them for you.

The only contract between the two sides is **data**: a draggable carries a `dragData` payload, and a zone reads it through `accepts` and `onDrop`.

## A complete drag → drop

A draggable file chip that carries a payload, and a zone that only accepts files and reacts when one is dropped. The zone gets a `data-neodrag-over` attribute while an accepted drag hovers it — style that to give feedback.

That is the whole feature: one draggable with `dragData`, one droppable with `accepts` + `onDrop`. The engine matches them.

## Reacting to a zone's state

Each binding exposes whether an accepted drag is currently over it, so you can drive UI without touching the DOM:

- **Svelte** — `zone.isOver` (a reactive getter)
- **React** — `const { ref, isOver } = useDroppable(...)`
- **Vue** — `const { ref, isOver } = useDroppable(...)` (`isOver` is a `Ref`)
- **Solid** — `const { ref, isOver } = createDroppable(...)` (`isOver` is an `Accessor`, call it)
- **Vanilla** — read `data-neodrag-over` from the node, or use the `onEnter`/`onLeave` callbacks

The engine also stamps the zone element with `data-neodrag-over` for the duration of an accepted hover — the cleanest way to style hover feedback in plain CSS:

```css
.zone[data-neodrag-over] {
  outline: 2px dashed hotpink;
  background: color-mix(in oklab, hotpink 12%, transparent);
}
```

## DropOptions

Everything a zone does is configured through its options.

### `accepts`

<AcceptsDemo client:visible />

`accepts?: ({ dragNode, data }) => boolean`

A filter that decides whether this zone reacts to a given drag. It receives the drag's DOM node and its `dragData`. Return `false` and the zone ignores the drag entirely — no enter/over/leave/drop events fire and `data-neodrag-over` is never set. Omit it to accept every drag.

```js
// Only accept cards from the "todo" column
accepts: ({ data }) => data?.column === 'todo',
```

### Lifecycle callbacks

All four receive a `DropEventData`:

```ts
DropEventData = { zone, dragNode, data, input }
```

- `zone` — the drop zone's node
- `dragNode` — the element being dragged
- `data` — the dragged item's `dragData` payload
- `input` — the originating pointer/keyboard input

| callback | fires |
|---|---|
| `onEnter` | an accepted drag first moves over the zone |
| `onOver` | every move while an accepted drag is inside the zone |
| `onLeave` | the drag exits the zone (or is dropped elsewhere) |
| `onDrop` | the drag is released over the zone |

### `priority`

`priority?: number` (default `0`)

When several zones overlap under the pointer, the highest `priority` wins the hit. Use it to layer a small zone on top of a larger one — give the inner zone a higher number so it claims the drop even though both rects contain the pointer.

```js
// inner trash icon beats the surrounding panel
const panel = new Droppable(panelEl, { priority: 0 });
const trash = new Droppable(trashEl, { priority: 10 });
```

Ties (equal priority) fall back to the collision policy.

### `hitExpand`

`hitExpand?: number` (default `0`)

Grows the zone's hit rectangle by N pixels on every side, without changing its layout. Handy for small targets that are hard to hit precisely, or to add a forgiving margin around a zone.

```js
// a 24px icon that's easy to drop onto
const zone = new Droppable(iconEl, { hitExpand: 16 });
```

### `collision`

`collision?: CollisionPolicy` (default `'pointer'`)

How the engine ranks a zone when deciding which one a drag is "over". One of:

| policy | hit when |
|---|---|
| `'pointer'` | the pointer is inside the zone rect (cheapest, the default) |
| `'closestCenter'` | rank by distance from the zone's center — the nearest center wins |
| `'closestEdge'` | rank by distance to the zone's nearest edge |
| `'intersection'` | rank by how much the dragged element's rect overlaps the zone |

`'pointer'` follows the cursor exactly. The other policies follow the dragged element's geometry, which feels better for large draggables where the cursor may sit off-center.

```js
const zone = new Droppable(zoneEl, { collision: 'closestCenter' });
```

### `native`

<NativeDemo client:visible />

`native?: boolean` (default `false`)

Opts the zone into **OS** drag-and-drop. Set it and the engine arms a native sensor on the shared engine, so a drag of files or selected text from your desktop or another application lands on the zone exactly like an in-app drag. The payload arrives on `onDrop` as `e.files` (a `File[]`) and `e.text` (a string) — both are only readable on the drop itself, never during hover.

```js
const zone = new Droppable(zoneEl, {
  native: true,
  onDrop: ({ files, text }) => {
    if (files?.length) upload(files);
    else if (text) insert(text);
  },
});
```

For a native drag, `accepts` receives `data: null` and a `types` array of the OS payload kinds (e.g. `'Files'`, `'text/plain'`) so you can gate on those instead of `dragData`.

## Collab: remote-hover presence

A drop carries **no synced op** — its outcome (upload, assign, place an order) is a local side-effect, not replayable state. But you *can* sync the **hover**: give the zone a stable `id` and add it to a [collab `Room`](./collab), and while a remote peer drags over the zone the engine sets `data-neodrag-remote-hover="<peerId>"` on it and floats a `data-neodrag-remote-hover-marker` element at their cursor — both yours to style.

```js
const zone = new Droppable(el, { id: 'inbox', onDrop: assign });
room.add(zone, 'inbox'); // now peers see each other hovering — still no `onDrop` replay
```

## Notes

- **No wiring.** A `Droppable` registers itself with the global drop engine on bind and observes every drag automatically. You never connect a draggable to a zone by hand.
- **`accepts` is the gate.** A rejected drag produces no events and no `data-neodrag-over` — both sides only ever see drags they care about.
- **The payload is yours.** `dragData` is `unknown`; put whatever object you like on the draggable and read it back in `accepts`/`onDrop`.
- **Cleanup.** Framework wrappers tear the zone down with the component; in vanilla call `zone.destroy()` yourself.
