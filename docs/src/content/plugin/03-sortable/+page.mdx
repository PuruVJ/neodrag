`SortableList` turns a container into a reorderable list or grid. You give it your **data** (`items`) and a way to **apply a reorder** (`onReorder`), then spread a per-row binding onto each item. The library owns the drag math, the placeholder, the FLIP animation and — if you opt in — cross-container transfer between lists that share a `group`.

Two things make sortable different from the other capabilities:

- It is **data-first**. You don't move DOM nodes; you hand the list your array and it tells you the new order. Your render stays the single source of truth.
- Reorders are **anchor-based move ops** (`{ itemId, afterId }`), not index splices. An anchor survives concurrent inserts and deletes, which is exactly why the same op can be replayed by a remote peer — this is the seam the [Collaboration layer](/docs/plugin/collab) plugs into.

## A basic list

Bind the container, then spread `list.row(item)` onto each item — never hand-write `data-sortable-key`. Pass the item itself; the key is derived from its `id`/`key` field, from the value itself for strings/numbers, or — for a plain object with neither — from its reference identity. (Keys ride along in collaborative move ops, so give items you sync a real `id`/`key`.) When a drag commits, `onReorder` fires with the reordered array; assign it back to your state and re-render.

```svelte
<script>
  import { SortableList } from '@neodrag/svelte';

  let items = $state([
    { id: 'a', label: 'Write the spec' },
    { id: 'b', label: 'Build the thing' },
    { id: 'c', label: 'Ship it' },
  ]);

  const list = new SortableList({
    get items() {
      return items;
    },
    onReorder: (next) => {
      items = next;
    },
  });
</script>

<ul {...list.attach}>
  {#each items as item (item.id)}

  {/each}
</ul>
```

```tsx
import { useState } from 'react';
import { useSortable } from '@neodrag/react';

function TodoList() {
  const [items, setItems] = useState([
    { id: 'a', label: 'Write the spec' },
    { id: 'b', label: 'Build the thing' },
    { id: 'c', label: 'Ship it' },
  ]);

  const { ref, row } = useSortable({
    items,
    onReorder: (next) => setItems(next),
  });

  return (
    <ul ref={ref}>
      {items.map((item) => (
        <li key={item.id} {...row(item)}>
          {item.label}
        </li>
      ))}
    </ul>
  );
}
```

```vue
  { id: 'a', label: 'Write the spec' },
```

```js
      return li;

  get items() {
    return items;
  },
  onReorder: (next) => {
    items = next;
    render();
  },
});

render();
```

> `row(item)` returns an object holding the `data-sortable-key` attribute. In Svelte/React/Solid you spread it (`{...list.row(item)}`); in Vue you bind it (`v-bind="row(item)"`). It is type-checked, so there is no stringly-typed attribute to get wrong.

### The options

| key          | type                          | meaning                                                                                  |
| ------------ | ----------------------------- | ---------------------------------------------------------------------------------------- |
| `items`      | `T[]`                         | the current ordered items — push a fresh snapshot whenever your data changes; keys come from each item's `id`/`key` field (or the value itself for strings/numbers) |
| `onReorder`  | `(next, op) => void`          | fired on commit with the reordered array **and** the anchor `MoveOp`                      |
| `axis`       | `'x' \| 'y'`                  | the active axis for a list (defaults to the layout direction)                            |
| `strategy`   | `'list' \| 'grid'`            | `list` = 1D midpoint crossing, `grid` = 2D closest-center. Default `list`                |
| `group`      | `string`                      | cross-container transfer group — lists sharing one can exchange items                    |
| `animation`  | `boolean \| number`           | FLIP on reorder. `true` → 200ms, a number → that many ms, `false` → off. Default `true`  |
| `lift`       | `boolean`                     | lift the dragged node onto `position: fixed` so it floats above its siblings. Default off |
| `hysteresis` | `number`                      | px the pointer must cross past a slot boundary before the gap flips. Default 3            |
| `onCommit`   | `(op) => void`                | pure op stream — fires the `MoveOp` on every commit (the collab seam)                     |
| `onTransfer` | `(op) => void`                | fires on the **target** list when an item transfers in from another container            |

`onReorder` hands you both representations of the same move: `next` is the convenient reordered array (assign it to state), and `op` is the `MoveOp` — `{ itemId, afterId }`, where `afterId` is the key the item now sits after (`null` means it moved to the front).

## A grid

Set `strategy: 'grid'` for a 2D arrangement — a photo wall, a board of cards, an icon grid. Instead of crossing midpoints along one axis, the dragged item snaps to the closest cell center. Everything else (data flow, `row()`, FLIP) is identical; only the targeting math changes.

<div slot="svelte">

```svelte
<script>
  import { SortableList } from '@neodrag/svelte';

  const grid = new SortableList({
    get items() {
      return photos;
    },
    strategy: 'grid',
    onReorder: (next) => {
      photos = next;
    },
  });
</script>

<div class="grid" {...grid.attach}>
  {#each photos as photo (photo.id)}
```

## Cross-container groups

Give two (or more) lists the same `group` string and they become transfer-aware: drag an item out of one and drop it into another. No wiring connects them — they discover each other by group identity. This is the kanban / Trello pattern.

When an item crosses over, `onReorder` fires on the **source** list (the item left, with its new order) and `onTransfer` fires on the **target** list with a `TransferOp` describing what arrived (`{ item, fromContainer, toContainer, from, to }`). Each list still owns its own slice of state — you move the item between the two arrays.

<FrameworkSwitch>
<div slot="svelte">

```svelte
<script>
  import { SortableList } from '@neodrag/svelte';

  let todo = $state([{ id: '1', text: 'Draft' }]);
  let done = $state([{ id: '2', text: 'Ship' }]);

  const todoList = new SortableList({
    get items() {
      return todo;
    },
    group: 'board',
    onReorder: (next) => {
      todo = next;
    },
    onTransfer: ({ item, to }) => {
      todo = [...todo.slice(0, to), item, ...todo.slice(to)];
    },
  });

  const doneList = new SortableList({
    get items() {
      return done;
    },
    group: 'board',
    onReorder: (next) => {
      done = next;
    },
    onTransfer: ({ item, to }) => {
      done = [...done.slice(0, to), item, ...done.slice(to)];
    },
  });
</script>

<div class="columns">
  <ul {...todoList.attach}>
    {#each todo as card (card.id)}
      <li {...todoList.row(card)}>{card.text}</li>
    {/each}
  </ul>
  <ul {...doneList.attach}>
    {#each done as card (card.id)}
      <li {...doneList.row(card)}>{card.text}</li>
    {/each}
  </ul>
</div>
```

## Animation and lift

By default reorders animate with **FLIP** (`animation: true`, 200ms): the library measures every row before and after the commit and plays the difference, so neighbours slide smoothly into their new slots. Pass a number to tune the duration, or `false` to turn it off.

`lift: true` pins the dragged node onto `position: fixed` while you hold it, so it floats above its siblings instead of pushing them around in flow — the chip-out-of-the-list feel. Use it for cards and tiles; leave it off for tight inline lists.

The library tags the in-flight node so you can style each phase from CSS — no extra config:

- `data-neodrag-sortable-dragging` on the node being dragged
- `data-neodrag-sortable-lifted` on the lifted node (when `lift` is on)
- `data-neodrag-sortable-placeholder` on the gap left behind in the flow

```css
[data-neodrag-sortable-dragging] {
  opacity: 0.9;
}

[data-neodrag-sortable-placeholder] {
  background: color-mix(in oklab, currentColor 8%, transparent);
}
```

## Real-time and collaboration

Because reorders are anchor-based `MoveOp`s, the exact same operation can be applied on a remote peer and converge — anchors commute where index splices clash. That's why every `SortableList` exposes two collab seams:

- **`onCommit(op)`** — the durable, op-only stream. Fires the `MoveOp` on every commit. This is what a collab adapter subscribes to in order to broadcast your local moves.
- **`applyExternal(op)`** — apply an inbound `MoveOp` from a remote peer through the same reorder path (Svelte/React/Solid/Vue expose this via the underlying list; vanilla calls it directly on the instance). Its companion `presence()` reports the in-flight drag so you can render remote cursors.

You rarely call these by hand — `bindCollab` wires `onCommit` → out and remote ops → `applyExternal` for you. See the [Collaboration page](/docs/plugin/collab) for the full CRDT-ready setup over Yjs, Liveblocks, or your own provider.
