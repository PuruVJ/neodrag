Draggable keeps a small, options-only core: `axis`, `bounds`, `grid`, `handle`, `cancel`, `position`, and the two always-on behaviors (`touchAction`, `userSelect`). Everything else — magnetic snapping, scroll locking, a floating ghost, haptics, accessibility announcements — lives behind one seam: the `use` option.

```ts
use?: DragPlugin[]
```

`use` takes an array of extensions. Each is a plain object — there is no reconcile machinery, no reactive slots, no lifecycle beyond three optional hooks. Extensions tree-shake to nothing unless you import them, so the core stays tiny while the long tail of behavior stays one import away.

Everything on this page imports from your framework package — `@neodrag/svelte`, `@neodrag/react`, `@neodrag/vue`, `@neodrag/solid`, `@neodrag/vanilla`. There is no separate plugins entry point.

## The `DragPlugin` shape

An extension is this object:

```ts
interface DragPlugin {
  name?: string;
  onStart?(ctx: DragEventData): void;
  onMove?(ctx: DragEventData): Point | void;
  onEnd?(ctx: DragEventData): void;
}
```

- `onStart` runs once when a drag begins.
- `onMove` runs every move tick. **Return a `{ x, y }` `Point` to override the offset** the core would otherwise apply; return nothing to leave it alone. This is how `magnetic`, `snapToGrid`, and `ghost` work.
- `onEnd` runs once when the drag ends.

Each hook receives the same `DragEventData`:

```ts
interface DragEventData {
  offset: Point;   // current offset { x, y }
  node: DndNode;   // the dragged element
  input: InteractionInput; // live pointer / keyboard input (clientX/Y, etc.)
}
```

That's the entire contract. The built-ins below are just objects that fill in these three hooks.

## Built-in extensions

All of these come from your framework package.

### `magnetic(targets, radius?)`

Snaps the offset to the nearest target point once the drag gets within `radius` px (default `24`). `targets` is a list of `{ x, y }` points.

<FrameworkSwitch>
<div slot="svelte">

```svelte
<script>
  import { Draggable, magnetic } from '@neodrag/svelte';

  const drag = new Draggable({
    use: [magnetic([{ x: 0, y: 0 }, { x: 200, y: 0 }], 30)],
  });
</script>

<div {...drag.attach}>Drag me</div>
```

</div>

### `onMove(fn)`

Fires `fn(offset)` on every move tick without changing the offset — analytics, telemetry, a live read-out. (This is the convenience wrapper; for a callback per move you can also use the core `onDrag` option.)

```ts
use: [onMove(({ x, y }) => console.log(x, y))];
```

### `scrollLock(opts?)`

Freezes scrolling, text selection, and native touch panning on a container for the duration of the drag, then restores the exact inline styles it touched.

```ts
scrollLock({
  lockAxis: 'both',        // 'x' | 'y' | 'both' — which native pan axis to forbid
  container: () => myEl,    // element or lazy getter; default document.documentElement
  allowScrollbar: false,    // keep the scrollbar (skip overflow: hidden)
});
```

### `controls` (built-in `DragOptions`, not a `use:` plugin)

Start-gating lives in the **`controls`** option on `Draggable`, so it hard-vetoes the start. `handle` = where a drag may begin, `cancel` = where it may not. A bare selector/element is the simple whitelist/blacklist; pass `ControlFrom.*` to resolve *overlapping nested* zones by area — the smallest zone containing the pointer wins, with `priority` breaking equal-area ties. Selectors go to `querySelectorAll`, so keep them static + trusted.

```ts
import { Draggable, ControlFrom } from '@neodrag/svelte';

new Draggable({ controls: { handle: '.titlebar', cancel: '.no-drag' } });

// nested zones:
new Draggable({
  controls: {
    handle: ControlFrom.selector('.drag-handle'),
    cancel: ControlFrom.selector('.no-drag'),
    priority: 'allow',
  },
});
```

### `autoScroll(opts?)`

Scrolls the nearest container when the pointer drifts into its edge margin.

```ts
autoScroll({
  margin: 48,            // edge band (px) inside which scrolling kicks in
  maxSpeed: 24,          // max px scrolled per move tick
  container: () => myEl,  // element or lazy getter; default the viewport
});
```

### `ghost(opts?)`

Drags a floating, pointer-transparent clone while the original stays put. The clone mounts in a shared overlay layer above everything.

```ts
ghost({
  opacity: 0.5,     // clone opacity
  zIndex: 2147483640, // clone z-index
});
```

### `haptics(opts?)`

Fires `navigator.vibrate` on start and (optionally) end. SSR-guarded; a no-op where the Vibration API is unsupported. Defaults to a single 10ms tap on start.

```ts
haptics({ start: 10, end: [20, 40, 20] }); // number or on/off ms sequence
```

### `ariaDrag(opts?)`

Announces the drag to an ARIA live region and marks the node grabbed — primarily for keyboard drags (pointer drags are already visible, so announcements are gated to keyboard input).

```ts
ariaDrag({
  role: 'button',
  label: 'Draggable',
  liveRegion: () => document.querySelector('#sr-status'),
  announce: { grab: true, move: true, drop: true }, // or a single boolean
});
```

## Authoring a custom extension

Because a `DragPlugin` is just an object with three optional hooks, writing your own is trivial. Return a `Point` from `onMove` to take over positioning; return nothing to observe only.

Here's a constraint that pins movement to a circle of a given radius around the origin:

```ts
import type { DragPlugin, Point } from '@neodrag/svelte';

function circular(radius: number): DragPlugin {
  return {
    name: 'circular',
    onMove({ offset }): Point {
      const dist = Math.hypot(offset.x, offset.y);
      if (dist <= radius) return offset;
      const scale = radius / dist;
      return { x: offset.x * scale, y: offset.y * scale };
    },
  };
}
```

Drop it into `use` like any built-in:

## The reactivity rule

This is the one thing to internalize about `use`:

> `use` is a **static array**. It is built once for the binding. The extension instances inside it stay alive for the lifetime of the draggable, so any internal state they keep is preserved and `onStart`/`onEnd` stay balanced.

That stability is the feature: a ghost clone, a saved scroll-lock style, a magnetic accumulator — none of it gets wiped mid-drag because the array never rebuilds.

So how do you make an extension react to changing config? **The hook reads live config at call time.** You have two ways to do that:

**1. A custom inline extension that closes over your reactive state.** The hook body reads the current value every move, so updating the state just changes the next tick's result.

<FrameworkSwitch>
<div slot="svelte">

```svelte
<script>
  import { Draggable } from '@neodrag/svelte';

  let targets = $state([{ x: 0, y: 0 }]);

  function snap(points, offset) {
    let best = offset, bestD = Infinity;
    for (const t of points) {
      const d = Math.hypot(t.x - offset.x, t.y - offset.y);
      if (d < bestD) { bestD = d; best = t; }
    }
    return bestD <= 30 ? best : offset;
  }

  // `use` stays static; the closure reads live `targets` each move.
  const drag = new Draggable({
    use: [{ onMove: ({ offset }) => snap(targets, offset) }],
  });
</script>

<div {...drag.attach}>Drag me</div>
```

</div>

**2. A built-in that reads a reactive object you hand it.** Pass a reactive object (not a bare value) and mutate its fields — the extension reads the object's current contents when it runs.

<FrameworkSwitch>
<div slot="svelte">

```svelte

  import { Draggable, magnetic } from '@neodrag/svelte';

  // A reactive object you mutate; magnetic reads cfg.targets live.
  const cfg = $state({ targets: [{ x: 0, y: 0 }] });
  const drag = new Draggable({ use: [magnetic(cfg.targets, 30)] });

  // Later: cfg.targets.push({ x: 200, y: 0 });
</script>

<div {...drag.attach}>Drag me</div>
```

Two things that do **not** work, by design:

- **A bare primitive passed to a factory is captured by value.** `snapToGrid(size)` reads `size` once when the factory runs; reassigning `size` afterward changes nothing. That's plain JavaScript — not a limitation we can fix. Wrap it in a reactive object or use an inline closure (option 1) instead.
- **Never make `use` itself a getter.** Unlike the core options (where getters are how you wire reactivity), a reactive `use` would rebuild the array and recreate every extension on each change — wiping ghost clones, saved styles, and any in-flight state. Keep `use` static; put the reactivity *inside* the hook.
